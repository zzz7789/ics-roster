# 待确认的业务边界

当前仓库只实现了「人员 × 日期 × 班次」的最小骨架，以下问题确定后再迭代，避免过早抽象。

## 1. 排班数据来源

- [x] 网页手动录入（已支持）
- [x] 导入已有 `.ics` 排班文件（已支持：预览分组 + 人工确认映射 + 幂等落库）
- [x] 外部排班算法生成后调用 `/api/shifts/bulk` 整批上传（接口已就绪）
- [ ] 循环排班模板（如「上一休二」）自动铺满一个月

## 2. ICS 生成位置与订阅方式

- [x] 服务端生成 + 订阅地址（已定：`/api/calendar/team.ics` 与 `/api/calendar/person/{id}/{token}.ics`）
- [ ] 是否需要额外提供一次性下载 `.ics` 文件的入口
- [ ] 事件标题格式是否要带班次时间 / 地点 / 备注

## 3. 权限与访问控制

- [ ] 目前无登录，接口全部公开（仅 ICS 订阅地址带 token）
- [ ] 是否需要管理员口令 / 多用户登录
- [ ] 是否需要按小组隔离数据

## 4. 可视化操作

- [ ] 当前是「人员为行、日期为列」的月视图网格
- [ ] 是否需要 week / day 视图
- [ ] 是否需要拖拽调整、批量刷班（刷一段日期）
- [ ] 是否需要统计视图（每人班次数、工时合计、夜班次数）

## 5. 其他

- [ ] 人员离职后保留历史（当前为软删除 `active=false`）
- [ ] 班次类型是否需要允许自定义时间跨天、半天假
- [ ] 是否需要操作日志（谁在什么时候改了哪个班）
- [ ] 时区固定 `Asia/Shanghai`，是否需要多站区支持
